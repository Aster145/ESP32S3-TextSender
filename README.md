# ESP32-S3 TextSender

Windows 桌面串口发送工具，将文本交给 ESP32-S3，由开发板的原生 USB 接口模拟键盘输入。支持编辑框、可编辑常用短语（含按键脚本短语）、可命名的多个项目及各自的脚本快捷按钮，以及读取所选 ns2jb / HBLauncher 项目的 `V=START` 连接口令。

当前版本 v1.11.0 为常用短语新增"脚本短语"：一条短语可以按顺序发送文字、按键、等待和启动项目脚本，间隔自定。脚本短语继续兼容 v1.3 固件，无需刷机。此前 v1.10.1 的键盘直通与默认开启的电脑快捷键屏蔽保持不变；键盘直通需要配套 TextKeyboard v1.4 固件，已刷 v1.4 无需再次刷机。原有文字、常用短语和 V=START 发送继续兼容 v1.3；仅使用这些功能时无需重新刷机。

[下载最新 Windows 便携版](https://github.com/Aster145/ESP32S3-TextSender/releases/latest)

## 开始使用

需要 Windows、.NET Framework 4.8，以及运行配套 TextKeyboard v1.3 或 v1.4 固件的 ESP32-S3；键盘直通需要 v1.4。目标设备应使用英文 / US 键盘布局。

1. 将程序放在可写目录，运行 `TextSender.exe`。从源码使用时，先按下方步骤构建。
2. 双 USB 开发板的 **UART / COM 接口接电脑**，**原生 USB / OTG 接口接收键盘输入的目标设备**。接口用途以开发板标注为准。
3. 选择 UART 对应的串口。若列表为空，检查数据线、开发板连接和 USB 转串口驱动，然后点击“刷新”。关闭占用同一串口的其他工具。
4. 将输入目标置于需要接收文字的位置，在编辑框输入内容，再点击发送；也可以点击常用短语按钮。

启动程序、切换项目和获取口令预览都不会自动发送按键。

程序使用键盘与发送箭头图标，并以单例模式运行：重复打开同一版本会唤起已有窗口，最小化后也会恢复；已有的文字、项目和串口连接保持不变。复制到其他目录的同版本程序也只运行一个，使用先启动那份程序的设置。退出已有窗口后，可以正常重新打开。升级前请先退出旧版程序。

## 键盘直通

先按 [固件说明](firmware/FLASHING.md) 将 ESP32-S3 更新为 TextKeyboard v1.4。保持原来的双线连接：UART / COM 接电脑，原生 USB / OTG 接收按键的目标设备。

选择串口后点击“键盘直通…”。连接成功后，在直通窗口中使用自己的键盘，按下、松开和持续按住都会转发；支持方向键、功能键、数字小键盘及组合键，例如 `W + Shift + 空格` 或 `Ctrl + C`。可同时按住 **6 个普通键和左右 Ctrl、Shift、Alt、Win 修饰键**，超过普通键数量时会提示。直通不使用文字发送的倒计时、逐字间隔或自动回车设置。

直通只在该窗口位于前台且未暂停时生效。点击“暂停直通”、切换到其他窗口或关闭直通时，会请求释放全部按键；切换窗口后需要点击“继续直通”恢复。断线时固件会在约 1 秒未收到按键状态更新后释放按键。直通期间不能同时发送文字或启动脚本；关闭后恢复原有功能。

“屏蔽电脑快捷键”默认开启。在直通窗口控制时，程序会提前拦截按键，阻止常见全局快捷键、Alt+Tab、Alt+F4、Win 键等交给电脑上的其他程序；按键仍正常发送给目标设备。需要操作电脑时，用鼠标点击“暂停直通”、关闭直通或点击其他窗口，立即解除接管。切换屏蔽选项也会先释放全部按键。开始和暂停前请先松开所有按键；若按住某键暂停，恢复后该键需松开后再按一次，避免旧持键意外重放。

按键按物理键位转发，目标设备自行决定键盘布局、大小写和长按重复行为，不传输电脑输入法生成的中文。屏蔽功能不提供系统级独占：Ctrl+Alt+Del、Win+L 等 Windows 保留快捷键，以及使用独立键盘驱动或其他底层输入方式的程序，仍可能响应；其他键盘钩子也可能相互影响。参见 [Microsoft 的键盘拦截说明](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc) 和 [保留快捷键及兼容性说明](https://learn.microsoft.com/en-us/windows/powertoys/keyboard-manager)。程序不记录键盘输入，暂停、失焦、断开或退出时停止拦截。

## 文本与常用短语

- 支持 ASCII 英文、数字、常见半角符号、换行和制表符；不支持直接发送中文内容。短语按钮名称可以使用中文。
- 单次最多 8192 字节，按换行规范化后的 ASCII 内容计算；追加回车也计入长度。超出长度或包含不支持的字符时，发送前会提示。
- “发送前等待”可设为 0～10 秒，步进 0.1 秒。**0 表示不额外倒计时**，首次打开串口仍需约 1.2 秒初始化。逐字间隔和换行等待另行设置；固件每次按键本身还会保持约 20 毫秒。
- “管理常用短语”支持新增、编辑、删除和为单条短语设置末尾回车。点击短语直接发送，不替换编辑框内容。
- 全局“发送后自动回车”默认关闭。开启后，未以换行结尾的短语会追加回车；与单条短语的追加选项同时开启时只追加一次。单条短语原有的明确追加行为保持不变。
- “清除回车后的自动缩进”仅用于 SmileBASIC 的 EDIT 编辑界面，用来保留原文缩进。普通输入通常不需要勾选。
- “停止”请求固件取消当前输入。“切换目标 Caps Lock”会实际发送 Caps Lock 按键。
- 发送完成后保留串口连接供下一次复用。更换串口、刷新串口列表、遇到通信错误或关闭程序时会释放连接。

程序显示完成，表示固件完成了发送流程；请在目标设备核对实际文字。

## 脚本短语（按键 + 间隔 + 启动脚本）

在“管理常用短语”中勾选**脚本模式**，一条短语就从纯文本变为按键脚本：点击按钮后按顺序执行每行指令。`#` 开头的行是注释，空行忽略，指令名和按键名大小写不限。

```text
TEXT Hello, target device!   # 发送文字
WAIT 2                       # 等待 2 秒（支持小数，0～60 秒）
KEY Enter                    # 按一下回车
TEXT Second message
KEY Backspace x3             # 退格连按 3 次（x1～x100）
WAIT 3
RUN FTP                      # 启动当前项目里名为 FTP 的脚本快捷按钮
VSTART                       # 读取并发送当前项目的最新 V=START 连接口令
```

- **TEXT**：发送 ASCII 文字，支持 `\n`（回车）、`\t`（Tab）、`\\`（反斜杠）转义，单段最多 8192 字符。逐字间隔和换行等待沿用主窗口当前设置。
- **KEY**：发送一个按键，按键名单可点“脚本语法…”查看：Enter、Backspace（退格）、Delete、Tab、Esc、方向键、Home/End、PageUp/PageDown、Insert、F1–F12、CapsLock 等；固件对连按使用约 30 毫秒间隔。
- **WAIT**：等待指定秒数，支持小数（如 `WAIT 0.5`），范围 0～60 秒。
- **RUN**：启动当前项目里该名称的脚本快捷按钮（“管理脚本…”中配置的 .cmd / .bat / .ps1）；名称不存在时会提示并停止后续步骤。
- **VSTART**：等同于主窗口的“获取并发送 V=START”按钮——执行到该行时读取当前项目的最新口令并发送（带末尾回车）；口令会话已过期时会提示并停止后续步骤。不需要参数。
- 脚本不使用“发送前等待”倒计时和“发送后自动回车”，间隔全部由 WAIT 控制。执行期间界面进入忙碌状态，随时可点击“停止”，包括等待中。
- “脚本语法…”按钮打开的说明由程序按实际支持的按键名单生成，与代码保持一致。
- 脚本短语与纯文本短语保存在同一个列表里；旧版本配置中的短语加载后仍是纯文本模式。该功能使用固件现有 TYPE2 与 KEY 命令，v1.3 / v1.4 固件均可使用，无需刷机。

## 保存多个项目并切换

点击“添加文件夹…”选择项目目录，也可以直接在“项目目录”中粘贴路径并按回车。支持项目根目录或其 `runs` 目录。

已添加的目录出现在“切换项目”列表中。在“项目名称”输入框中填写名称，按回车或离开输入框即可保存。下拉列表同时显示名称和路径；可以给不同项目起同一个名称，通过路径区分。改名不会改变项目目录。

每个项目分别保存自己的脚本快捷列表。从下拉列表选择项目，或在“项目目录”中输入路径并确认后，“启动脚本”区域会显示该项目的按钮。项目切换不会启动脚本。

项目列表、名称和当前选择会保存。大小写、末尾斜杠，以及同一项目的根目录 / `runs` 两种选法会去重。“移除项目”只移除保存的项目条目，不删除项目文件夹或脚本文件。

程序只读取**当前选中项目**的口令，不会在全部已保存项目中寻找最新文件。目录不可用时会清空预览并提示，不会转用另一项目。

## 获取并发送 V=START

1. 按对应项目自己的流程启动 ns2jb / HBLauncher，等待它生成本次连接口令，并保持主机程序运行。
2. 在 TextSender 中选择本次实际运行的项目。
3. “获取最新”只读取和预览；目标设备准备好后，点击“获取并发送 V=START”。

程序在选中项目的 `runs/switch2-*/connect.txt` 和 `runs/launcher-*/connect.txt` 中，按文件修改时间选择最新会话。发送按钮会重新读取文件，发送整行并追加一次回车，不使用过期预览。该按钮使用当前的时间设置，但不执行 EDIT 自动缩进清理。

最新会话已存在 `connection.json` 或 `result.json`、口令格式无效，或者本机没有对应监听地址和端口时，会提示而不发送。程序只检查本机监听表，不主动连接该网络端口，也不退回更旧的会话。

### HBLauncher 口令导出接入

如果主机程序只在终端显示口令，需要在它现有的 `onWaiting` 回调中，将**本次实际生成的完整 `V=START(...)` 指令**写入当前 `runs/launcher-*` 会话目录的 `connect.txt`：UTF-8 编码、单行文本。回调参数和变量名应以所用主机项目为准，不要硬编码口令。

本仓库提供读取端，不附带第三方主机项目的完整文件，也不会自动修改 ns2jb / HBLauncher。主机项目的安装、启动和目标设备准备步骤仍按其自身说明执行。

## 多个脚本快捷按钮

主窗口的“启动脚本”区域显示**当前项目**的快捷按钮，例如 FTP、项目启动器或其他常用脚本。每个项目可以保存不同的按钮名称、脚本路径和工作目录。公开版默认没有项目或脚本，不附带脚本或服务。

1. 先选择项目，再点击“管理脚本…”并新增一项，填写按钮名称。
2. 粘贴脚本的完整文件路径，或通过文件选择器选择 `.cmd`、`.bat` 或 `.ps1` 文件。此字段只填写路径，不追加命令行参数；带外围双引号的路径也可以粘贴。
3. 按需填写或选择完整工作目录。留空时使用脚本所在目录；需要从项目根目录运行的脚本，可以在这里指定项目根目录。
4. 点击“保存”应用修改，主窗口会显示各项名称对应的按钮。之后可再次打开管理窗口改名、修改路径或删除快捷项；“取消”不应用本次修改。管理窗口只修改当前项目，其他项目的脚本保持原样。删除快捷项不会删除脚本文件。

点击快捷按钮才会启动该脚本。路径或工作目录暂时不可用时，配置仍可保留和编辑，启动时会提示缺失。`.ps1` 使用系统 PowerShell 的 `-NoProfile -File` 参数运行，沿用当前执行策略；系统禁止执行 PowerShell 脚本时，`.ps1` 也会被拒绝运行。请按所用脚本的说明准备运行环境。

启动脚本不会自动切换当前项目或发送连接口令。原有 FTP 脚本也可以作为其中一个快捷按钮使用。

## 配置与便携使用

设置保存在 EXE 同目录的 `settings.xml`，包括时间参数、常用短语、自动回车、置顶选项、项目列表和当前项目。每个项目保存名称、目录及自己的脚本快捷列表；每个脚本快捷项保存名称、脚本路径和可选工作目录。移动程序时一并保留该文件；目录不可写时，程序会明确提示保存失败。

升级时，旧项目列表及当前项目会迁入新的 `Projects` 列表。旧版全局脚本会分别复制到每个已有项目，之后独立保存：在一个项目中改名、修改路径或删除按钮，不影响其他项目。后续新增项目从空脚本列表开始。

如果旧配置尚未保存任何项目，原有脚本先保留为未分配脚本，首次添加项目时归入该项目。更早版本的 `FtpScriptPath` 也仍可迁移为名为“FTP”的脚本项。明确保存为空的列表不会从旧字段重新生成条目。升级保留原有短语和延迟设置。

已有旧版时，只替换 `TextSender.exe` 和说明文件，保留自己的 `settings.xml`；不要用新压缩包中的空白初始配置覆盖它。

`settings.example.xml` 是可公开的初始配置，不含预填项目、个人路径或连接口令。实际使用生成的 `settings.xml` 属于本地配置，已被 `.gitignore` 排除；不要将自己的配置或 `connect.txt` 提交到公开仓库。

## 从源码构建

不需要 NuGet 依赖或安装 Visual Studio。`build.cmd` 优先使用系统的 64 位 .NET Framework C# 编译器，找不到时使用 32 位版本。

在仓库目录运行：

```bat
build.cmd
```

输出为 `dist/TextSender.exe`。构建脚本会复制本说明；仅当 `dist/settings.xml` 不存在时，才从 `settings.example.xml` 创建初始配置，不覆盖已有设置。

主要文件：

```text
src/
  TextSender.cs              Windows 界面、串口发送和本地设置
  PresetScript.cs            脚本短语的指令解析与按键名单
  SenderApplication.cs       单例启动、窗口唤起及图标资源
  KeyboardPassthrough.cs     多键状态映射和实时串口会话
  KeyboardCaptureHook.cs     直通期间拦截电脑快捷键
  KeyboardPassthroughForm.cs 前台键盘直通窗口、暂停和释放
  StartTokenReader.cs        按项目读取与检查连接口令
  ExplorerFolderPicker.cs    原生 Windows 文件夹选择器
assets/TextSender.ico         程序、窗口及任务栏图标
firmware/TextKeyboard/
  TextKeyboard.ino           配套 v1.4 固件源码
settings.example.xml         无个人数据的初始配置
build.cmd                    Windows 构建脚本
test.cmd                     构建并运行离线与界面逻辑检查
tests/                       使用隔离配置和会话文件的检查源码
```

完整检查可在命令提示符中运行：

```bat
test.cmd
```

脚本先构建程序，再检查编码与协议参数、口令读取、项目命名与切换、按项目保存脚本和旧配置迁移、短语自动回车、脚本短语的解析与校验，以及脚本工作目录和启动参数。单例检查会在隔离目录实际启动程序，验证重复启动、最小化恢复、不同目录的副本及关闭后重启。测试使用隔离的配置和会话文件；不会运行用户配置的脚本、打开串口或发送 HID 按键。

也可以单独运行程序内置的离线自检：

```bat
start "" /wait dist\TextSender.exe --test-offline dist\offline-report.txt
type dist\offline-report.txt
```

离线自检不打开串口、不发送 HID 按键。它验证编码、协议参数及设置等逻辑，不代表已在目标设备完成输入测试。

## 固件下载与源码

仓库包含 **TextKeyboard v1.4 / ESP32-S3 / 16MB Flash** 固件源码 `firmware/TextKeyboard/TextKeyboard.ino` 和 `RawHidProtocol.h`。键盘直通需要这个版本，构建与刷写方法见 [刷写说明](firmware/FLASHING.md)。

- [下载 v1.4 固件压缩包（支持键盘直通，含 BIN、源码和刷写说明）](https://github.com/Aster145/ESP32S3-TextSender/releases/download/v1.10.0/ESP32S3-TextKeyboard-v1.4-16MB.zip)

旧版 v1.3 仍可下载，用于原有文字发送功能：

- [v1.3 固件压缩包（不支持键盘直通）](https://github.com/Aster145/ESP32S3-TextSender/releases/download/v1.7.1/ESP32S3-TextKeyboard-v1.3-16MB.zip)

合并镜像从 **0x0** 写入整个 16MB Flash，会覆盖现有程序和存储数据。此包仅用于匹配配置的 ESP32-S3；仅使用原有文字发送功能时，已有配套 v1.3 固件可以继续使用。

源码面向 Arduino ESP32 的原生 USB OTG 模式，构建注释要求 `USBMode=0`、`CDCOnBoot=cdc`。UART0 使用 115200 波特率、RX GPIO44、TX GPIO43；原生 USB 同时提供 HID 键盘和 CDC 命令接口。具体开发板的引脚连接、Flash / PSRAM 选项及烧录参数应按板型确认。

电脑与键盘输入目标是不同设备时，使用前述 UART + 原生 USB 双线连接。该仓库不会在启动桌面程序时刷写开发板固件。
